# 00_policy.md - 開発方針

## 1. 目的

本リポジトリは、閉域または庁内ネットワーク環境で利用する小規模な内部業務支援ツールを、継続的かつ効率的に開発するための共通方針・設計前提・品質基準をまとめたものである。

主な目的は、個別ツールを毎回フルスクラッチで作成する状態を避け、画面構成、共通処理、注意事項、配布方法、保守方法を標準化することである。

本リポジトリは、基幹システムを代替するものではなく、閉域環境における職員の隙間業務を支援する小規模ツールを、継続的に作成・再利用するための開発基盤である。

この文書は、Vibe-codingで新規ツールを作成または修正する際に、個別のシステム設計書とは別に、AIへ毎回渡す共通前提文書として利用する。

---

## 2. 位置づけ

本リポジトリの中核は、特定のコードライブラリやフレームワークではなく、閉域自治体向け内部ツール開発のための「開発ガードレール」である。

そのため、最初から過度な共通部品化を目指さない。

まずは、以下を優先する。

1. 開発方針の明文化
2. AIに守らせる実装ルールの整備
3. 個別ツール設計時の確認観点の標準化
4. README、チェックリスト、注意事項の標準化
5. 繰り返し発生する実装のみ、後から共通部品化する

---

## 3. 対象とするツール

本方針で対象とするのは、以下のような内部業務支援ツールである。

- 職員が庁内端末から利用する簡易Webツール
- ファイル整理、CSV処理、帳票補助などの事務処理支援ツール
- 閉域環境またはインターネット接続に制約がある環境で動作するツール
- 基幹システムを代替せず、職員の確認・転記・整形・判断補助を行うツール
- 小規模に作成し、必要に応じて庁内で横展開できるツール
- JavaScript、PowerShell、C# のいずれかで構築する内部向けツール

---

## 4. 対象外

以下は、原則として本リポジトリの対象外とする。

- 住民向け公開サービス
- 基幹系システムの代替
- 公式記録を保存・管理するシステム
- 高度な認証・権限管理を必要とする業務システム
- 個人情報を継続的に蓄積するシステム
- 法令上または業務上、正規システムとしての保証が必要なもの
- 所管部署の正式な業務判断を自動化・代替するもの
- 組織全体の標準業務システムとして厳格なSLAを求められるもの

---

## 5. 基本思想

本リポジトリの基本思想は以下のとおりである。

1. 閉域環境で動作することを優先する
2. 外部通信を前提にしない
3. 外部CDNを使用しない
4. 追加ソフトウェアの導入を前提にしない
5. 基幹システムや公式記録を代替しない
6. 処理結果は必ず職員が確認する
7. 個人情報を保存しない、または最小限に扱う
8. 操作が簡単で、説明を読まなくても概ね使えることを目指す
9. 小さく作り、必要に応じて育てる
10. Vibe-codingで再利用しやすい構成にする
11. 毎回フルスクラッチで作らず、既存方針・既存設計・既存部品を優先する
12. 流行技術よりも、閉域環境での運用容易性、説明容易性、保守性を優先する
13. ツールの出力は補助であり、最終判断は利用者または所管部署が行う

---

## 6. 対象環境

原則として、以下の環境で動作することを想定する。

- Windows端末
- 庁内ネットワークまたは閉域ネットワーク
- 標準ブラウザ
- IIS等による静的ファイル配布
- PowerShellが利用可能な環境
- .NET / C# が利用可能な環境

ただし、ツールごとに利用可能な環境は異なるため、各ツールのREADMEに前提条件を明記する。

---

## 7. 原則として前提にしないもの

以下は、原則として前提にしない。

- インターネット接続
- 外部API
- クラウドサービス
- npm等によるオンラインパッケージ取得
- 外部CDN
- 管理者権限を必要とするインストール
- データベースサーバー
- 常駐サービス
- サーバーサイド実行環境
- 複雑なビルド環境
- 利用者端末への追加インストール

---

## 8. 使用する言語と役割

本リポジトリでは、主に以下の3種類の言語を使用する。

| 言語 | 主な役割 | 想定用途 |
|---|---|---|
| JavaScript | 職員向けWebツール | IIS配置、ブラウザ上で動作する便利ツール |
| PowerShell | 事務処理・運用補助 | ファイル整理、CSV処理、Office補助、配布作業、ログ処理 |
| C# | 安定運用向けアプリ | GUIツール、重い処理、exe配布、長期利用ツール |

### 8.1 JavaScript

JavaScriptは、職員がブラウザで利用する小規模Webツールの主力とする。

HTML / CSS / JavaScriptで完結し、サーバーサイド処理を前提にしない。

主な用途は以下のとおり。

- 和暦・西暦変換
- 年度計算
- 日付計算
- QRコード生成
- 全角半角変換
- テキスト整形
- 個人情報マスキング補助
- CSV簡易チェック
- 文章テンプレート生成
- 申請内容の転記補助
- 郵便料金・手数料などの確認補助

### 8.2 PowerShell

PowerShellは、主に開発者または運用担当者が使用する自動化・一括処理用とする。

ファイル操作、ログ出力、バックアップ、CSV処理、Office関連の補助処理に使用する。

主な用途は以下のとおり。

- フォルダ作成
- ファイル名整理
- CSV結合
- Excelファイルの一括処理
- Word/PDFの整理
- Outlookメール保存
- 添付ファイル抽出
- IIS配置用ファイルのコピー
- ログ出力
- バックアップ
- 定型フォルダ生成

### 8.3 C#

C#は、JavaScriptやPowerShellでは扱いにくい処理、または職員向けにexeとして安定配布したい処理に使用する。

最初から多用せず、必要性が明確な場合に採用する。

主な用途は以下のとおり。

- Windows用GUIアプリ
- 大量ファイル処理
- PDF・画像・Officeファイル処理
- 正規表現や変換処理を高速・安定させたいもの
- 職員に配布する単体exe
- ある程度長く使う内部ツール
- PowerShellでは保守しづらくなった処理

## 9. 技術選定の原則

技術選定は、流行や高度さよりも、閉域環境での運用容易性、説明容易性、保守性を優先する。

### 9.1 優先するもの

- HTML / CSS / JavaScriptのみで動作する構成
- PowerShell標準機能で完結する処理
- .NET標準機能で実装できるC#ツール
- IIS等に配置するだけで利用できる静的Webツール
- 職員端末に追加インストールを求めない構成
- 設定ファイルやREADMEで動作条件を説明できる構成
- 小規模に作成し、必要に応じて拡張できる構成
- 閉域環境で再現可能な構成

### 9.2 慎重に扱うもの

- npm、NuGet等の外部パッケージ
- 外部API
- クラウドサービス
- サーバーサイド実行環境
- データベース
- 常駐サービス
- 高度な認証・権限管理
- 複雑なビルド手順を必要とする構成
- 利用者端末ごとの差異が大きい構成

### 9.3 外部ライブラリを使用する場合

外部ライブラリを使用する場合は、以下を満たすこと。

- ライセンスを確認する
- ファイルをローカルに同梱する
- CDN参照にしない
- バージョンを固定する
- 使用理由をREADMEに記載する
- 代替手段がある場合は比較する
- 更新方法を明記する
- 閉域環境で再現可能な状態にする

## 12. UI/UX方針

職員が短時間で使えることを優先し、画面は簡潔にする。

### 12.1 原則

- 操作手順を少なくする
- 入力欄、実行ボタン、結果表示欄を明確に分ける
- エラー時は原因と対応を表示する
- 成功時は次に何をすればよいか表示する
- 専門用語を避ける
- 説明文は短くする
- 重要な注意事項は画面上に表示する
- コピー、ダウンロード、印刷などの操作を分かりやすくする
- 見た目と操作感を可能な範囲で統一する
- 利用者が迷う設定項目を増やしすぎない

### 12.2 標準画面構成

Webツールは原則として以下の構成とする。

1. ツール名
2. 何をするツールかの短い説明
3. 入力欄
4. 実行ボタン
5. 結果表示欄
6. コピー・ダウンロード・印刷等の操作
7. 注意事項
8. 更新日・バージョン

---

## 13. セキュリティ・個人情報方針

本リポジトリで作成するツールは、個人情報や機微情報の取扱いに注意する。

### 13.1 原則

- 個人情報を保存しない
- 入力内容を外部送信しない
- ログに個人情報を残さない
- 処理結果を自動保存しない
- 必要な場合のみ、利用者操作によりダウンロードさせる
- 一時ファイルを作成する場合は保存場所を明記する
- 業務上必要な範囲を超えてデータを保持しない
- サンプルデータには実在の個人情報を使用しない
- 個人情報を扱う可能性があるツールでは、READMEと画面上に注意事項を記載する

### 13.2 標準注意文

各ツールには、必要に応じて以下の注意文を記載する。

```text
本ツールは庁内事務の補助を目的とした簡易ツールです。
基幹システム、公式記録、法令判断、最終的な業務判断を代替するものではありません。
出力結果は、利用者が必ず確認したうえで使用してください。
```

---

## 14. ファイル・データ取扱方針

ファイルを扱うツールでは、元ファイルを破壊しないことを優先する。

### 原則

- 元ファイルを直接上書きしない
- 加工結果は別ファイルとして出力する
- 上書きが必要な場合はバックアップを作成する
- ファイル名に使用できない文字を除去する
- 文字コードを明記する
- CSV出力では必要に応じてUTF-8 BOM付きにする
- 処理対象フォルダを明示する
- 大量ファイル処理ではログを残す
- 再実行時の挙動を明記する
- 処理失敗時の復旧方法を可能な範囲で記載する

---

## 15. 共通化の判断基準

すべてを最初から共通化しない。

同じ処理が複数回登場した場合、または今後も再利用する可能性が高い場合に共通化する。

目安として、同じ処理が3回以上登場した場合に、共通部品化を検討する。

### 15.1 共通化してよいもの

- 和暦・年度計算
- 日付処理
- 文字列整形
- ファイル名整形
- CSV入出力
- メッセージ表示
- エラー表示
- ログ出力
- バックアップ処理
- クリップボードコピー
- ダウンロード処理
- 印刷補助

### 15.2 共通化に慎重になるもの

- 個別業務に強く依存する処理
- 例外条件が多い処理
- 設定だけで無理に汎用化しようとする処理
- 読み手が理解しづらくなる抽象化
- 一度しか使わない可能性が高い処理
- 所管部署の業務ルールに依存する判断処理

## 16. Vibe-coding利用方針

Vibe-codingを利用する場合は、毎回ゼロから作らせず、本リポジトリの方針、テンプレート、共通前提に従わせる。

### 16.1 原則

- 既存方針を前提に実装する
- 既存ファイル構成を尊重する
- 共通化済みの処理がある場合は再利用する
- 個別機能はなるべく個別ファイルに閉じ込める
- 既存の動作を壊さない
- 変更理由をREADMEまたはコメントに残す
- セキュリティ、個人情報、閉域環境の制約を毎回明示する
- フルスクラッチで作り直さない
- 不要なライブラリや複雑な構成を追加しない
- 動作確認方法をREADMEに残す

### 16.2 Vibe-coding時の基本指示

Vibe-codingで新規作成または修正を依頼する場合は、以下の内容を基本指示として含める。

```text
このリポジトリは、閉域自治体向けの内部業務支援ツール群です。

外部CDN、外部API、クラウドサービス、追加インストールを前提にしないでください。
既存の方針、設計前提、共通部品を優先して利用し、フルスクラッチで作り直さないでください。
個人情報を保存・送信しない設計にしてください。
処理結果は利用者が確認して使用する前提としてください。
基幹システム、公式記録、法令判断、最終的な業務判断を代替しない補助ツールとして設計してください。
```

## 18. バージョン管理・リリース方針

各ツールは、可能な範囲でバージョンを付与する。

### 18.1 バージョン例

- `v0.x.x`: 試作・検証版
- `v0.9.x`: リリース候補版
- `v1.0.0`: 初回安定版
- `v1.x.x`: 機能追加・改善
- `v1.x.1`: 軽微な修正

### 18.2 リリース前確認

リリース前に、最低限以下を確認する。

- 閉域環境で動作するか
- 外部通信が発生しないか
- READMEがあるか
- 注意事項が表示されているか
- 入力エラー時の表示があるか
- 元ファイルを破壊しないか
- 個人情報を保存していないか
- サンプルデータで動作確認したか
- バージョン番号を更新したか
- 既知の制約をREADMEに記載したか

## 19. 保守方針

本リポジトリのツールは、小規模な内部業務支援を目的とする。

必要以上に保守責任を拡大しない。

### 原則

- 使われているツールを優先して保守する
- 使われていないツールは無理に維持しない
- 業務ルール変更時は利用部署側でも確認する
- 基幹システム変更に追随する保証はしない
- 問い合わせ先や保守範囲をREADMEに記載する
- 試作版、検証版、本番相当版の違いを明記する
- 正式運用する場合は、所管部署と運用ルールを確認する

---

## 20. 禁止事項

原則として、以下は禁止する。

- 外部CDNの利用
- 利用者の入力情報を外部送信すること
- 個人情報をログに保存すること
- 元ファイルを確認なしに上書きすること
- 管理者権限を当然の前提にすること
- 基幹システムの正規処理を迂回すること
- 法令判断や最終判断をツールに委ねること
- 所管部署の業務ルールを確認せずに公式運用すること
- 閉域環境で再現できない構成にすること
- 説明できない外部ライブラリを組み込むこと
- 利用者が気づかない形でファイルやデータを保存すること

## 22. まとめ

本リポジトリでは、立派な業務システム基盤を目指すのではなく、閉域自治体環境で使いやすい小規模な内部業務支援ツールを、継続的に作成・再利用できる状態を目指す。

重要な方針は以下の3点である。

1. 閉域・庁内・小規模補助ツールであること
2. JavaScript / PowerShell / C# を用途別に使い分けること
3. Vibe-codingで毎回フルスクラッチに戻らないこと

本方針により、個別ツールの開発効率、品質、説明責任、保守性を高める。
