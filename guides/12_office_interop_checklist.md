# 12_office_interop_checklist.md - Office Interopツール確認チェックリスト

## 1. 目的

- Office Interopを利用するC#ツールで、環境差異やCOM例外によるトラブルを減らす。
- 実機確認が必要な項目を明確にする。
- 管理者、運用担当部署、利用者それぞれの確認範囲を整理する。

## 2. 前提確認

- [ ] 利用端末に対象Office製品がインストールされている
- [ ] Officeのエディションを確認した
- [ ] Officeのバージョンを確認した
- [ ] Officeのビット数を確認した
- [ ] ライセンス上、当該利用が問題ないか確認した
- [ ] 利用者権限でOfficeを起動できる
- [ ] 初回起動時のOffice設定画面が表示されない状態で確認した
- [ ] 対象ファイル形式を開けることを確認した

## 3. C# / .NET 確認

- [ ] 対象.NETバージョンを確認した
- [ ] `dotnet build` 相当の確認を行った
- [ ] ビルド未確認の場合は理由を記録した
- [ ] 対象端末で実行確認を行った
- [ ] exe配布時の実行方法をREADMEに記載した

## 4. Office Interop 実行確認

- [ ] Officeアプリの起動に成功する
- [ ] Officeアプリの終了処理が行われる
- [ ] 変換後にOfficeプロセスが残らない
- [ ] 例外発生時にも終了処理が行われる
- [ ] COMオブジェクト解放を考慮している
- [ ] 複数回連続実行してもプロセスが残らない
- [ ] 入力ファイルが不正な場合にエラー表示される
- [ ] 出力先が存在しない場合にエラー表示される
- [ ] 既存ファイルがある場合に上書き確認される

## 5. COM例外時の対応

- 起動失敗時のエラー表示
- 変換失敗時のエラー表示
- 保存失敗時のエラー表示
- 再試行するかどうかの判断
- 自動再試行する場合の回数上限
- 自動再試行しない場合の利用者向け案内
- Word / Excel プロセス残留時の確認手順
- 手動終了が必要な場合の案内
- 管理者またはDX担当へ相談する条件

## 6. セキュリティ・個人情報

- [ ] 入力本文や変換対象文書をログ保存していない
- [ ] 外部通信していない
- [ ] 一時ファイルの保存場所を明記した
- [ ] 一時ファイルの削除方針を明記した
- [ ] 出力ファイルの保存先を利用者が確認する
- [ ] 個人情報を含む文書を扱う場合の注意をREADMEに記載した

## 7. 運用引継ぎ

- [ ] 管理者向け手順書にOffice依存を記載した
- [ ] 運用担当部署向け手順書に一次対応を記載した
- [ ] 利用者向け手順書にWord / Excel起動失敗時の案内を記載した
- [ ] 障害時に確認すべき事項を整理した
- [ ] 保守範囲と保守対象外を明記した


## 8. 実機未確認時の記録テンプレート

Office Interopを利用するツールでは、開発環境と実利用環境の差異により、実機確認が重要です。

ただし、開発段階では実機確認ができない場合があるため、その場合は「確認済み」とせず、未確認事項として記録してください。

| 確認項目 | 状態 | 未確認理由 | 想定リスク | 次に確認すること | 再確認期限 | 確認担当 | 備考 |
|---|---|---|---|---|---|---|---|
| Office製品の有無 | 未確認 | 実利用端末未準備 | ツール起動不可 | 実利用端末でWord起動確認 | YYYY-MM-DD | 利用部署 / 管理者 |  |
| Officeバージョン | 未確認 | 端末情報未取得 | Interop挙動差異 | Wordのバージョン確認 | YYYY-MM-DD | 管理者 |  |
| Office 32bit / 64bit | 未確認 | 端末情報未取得 | COM参照・起動失敗 | Officeのビット数確認 | YYYY-MM-DD | 管理者 |  |
| ライセンス | 未確認 | 所管確認前 | 利用条件不適合 | ライセンス条件確認 | YYYY-MM-DD | 管理者 / 所管部署 |  |
| COM例外発生時 | 未確認 | 異常系未再現 | 変換失敗時の案内不足 | 例外発生時の表示確認 | YYYY-MM-DD | 開発者 / 管理者 |  |
| プロセス残留 | 未確認 | 実機連続実行前 | WINWORD.EXE残留 | 複数回実行後に確認 | YYYY-MM-DD | 管理者 |  |
| 実利用端末での起動確認 | 未確認 | 実利用端末での検証日程未確定 | 業務端末でのみ発生する不具合を見落とす | 利用部署端末で起動・変換・保存を確認 | 未定（理由を備考へ記載） | 利用部署 / 管理者 |  |

### 記録時の考え方

- 実機確認できていない項目を「確認済み」と扱わない。
- 未確認項目は、リリース可否判断時に明示する。
- 試作版・検証版では未確認項目が残ることはあり得る。
- 本番相当利用前には、実利用端末での確認を原則とする。
- 未確認理由、想定リスク、次アクションを記録する。
- 32bit / 64bit差異は、Office Interop利用時の重要確認項目として扱う。
- 未確認項目には、再確認期限と確認担当を設定する。
- 再確認期限が未定の場合は、その理由を記録する。

## 9. Office 32bit / 64bit 差異の確認順

1. 実利用端末でOfficeのビット数を確認する。
2. 開発・検証端末と実利用端末のビット数が同じか確認する。
3. 異なる場合は、実利用端末側で起動・変換・保存を確認する。
4. COM起動失敗や参照エラーが発生する場合は、エラー内容を記録する。
5. 配布対象端末に複数のOffice構成がある場合は、代表端末ごとに確認する。
6. 確認できない構成は「未確認」として記録し、利用条件に含めるか判断する。
