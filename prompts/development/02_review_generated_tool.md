# 02_review_generated_tool.md

以下の条件で、生成済み内部ツール（コード + ドキュメント）をレビューし、依頼範囲で修正可能な問題は修正してください。

## 前提（必須参照）

- `guides/00_policy.md`
- `guides/01_ai_coding_rules.md`
- `guides/05_release_checklist.md`
- `guides/08_test_scenarios_template.md`
- `examples/01_filename_sanitizer/`

## レビュー観点（必須）

- `guides/00_policy.md` に反していないか
- `guides/01_ai_coding_rules.md` に反していないか
- ガイドの閉域・データ保護方針を満たすか
- READMEが十分か
- エラー表示が分かりやすいか
- 再実行時に破綻しないか
- リリース前チェックとテストシナリオが埋まっているか
- 通常業務に支障する問題を優先しているか
- 不要な機能・抽象化・文書を増やしていないか

## 入力情報（この下を埋めて使用）

- レビュー対象ファイル一覧:
- 想定利用環境:
- 既知の懸念点:

## 出力形式（この順序を厳守）

1. 総評
2. 重大な問題
3. 軽微な問題
4. 不足しているドキュメント
5. 実施した修正（修正不能なら理由付きの修正提案）
6. リリース可否（可 / 条件付き可 / 不可）
7. 次に確認すべきこと

## 出力ルール

- 指摘は「対象ファイル」と「該当箇所」が分かるように書く。
- 重大な問題は、修正しない限りリリース不可とする。
- 修正提案は可能な限りそのまま反映できる文面で示す。
- 確認可能なテストと文書整合まで行い、未確認は理由・リスク・次アクションを示す。
