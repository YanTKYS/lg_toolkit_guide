# 07_prompt_template.md - Vibe-coding用プロンプトテンプレート

## 使い方

- 依頼時に、用途に合うテンプレートをコピーして使う。
- すべてのテンプレートで、`docs/00_policy.md` と `docs/01_ai_coding_rules.md` を前提にする。
- 必要に応じて `docs/03`〜`docs/06` も併せて参照させる。

---

## 1. 新規ツール作成依頼テンプレート

以下の前提を必ず守って、新規ツールを作成してください。

- `docs/00_policy.md` と `docs/01_ai_coding_rules.md` を最優先で遵守すること。
- 閉域/庁内ネットワークで動作すること。
- 外部通信、外部API、外部CDN、クラウド依存を入れないこと。
- 個人情報を保存・送信・ログ出力しないこと。
- 元ファイル上書きや削除などの破壊的処理は原則避けること。

### 依頼内容

- ツール名:
- 使用言語（JavaScript / PowerShell / C#）:
- 想定利用者:
- 解決したい業務課題:
- 入力:
- 出力:
- 必須要件:
- 対象外:

### 出力してほしいもの

- 実装コード
- README（`docs/06_readme_template.md` 準拠）
- 注意事項表示
- リリース前確認ポイント

---

## 2. 既存ツール修正依頼テンプレート

以下の前提を必ず守って、既存ツールを最小変更で修正してください。

- `docs/00_policy.md` と `docs/01_ai_coding_rules.md` を最優先で遵守すること。
- 既存構成を尊重し、不要な全面改修をしないこと。
- 外部依存を増やさないこと。
- 個人情報・ファイル安全性を悪化させないこと。

### 修正対象

- 対象ファイル:
- 現在の問題:
- 期待する挙動:
- 影響範囲:

### 出力してほしいもの

- 変更内容の要約
- 修正コード
- 既存READMEへの追記案
- 回帰確認観点

---

## 3. コードレビュー依頼テンプレート

以下の前提でレビューしてください。

- `docs/00_policy.md` と `docs/01_ai_coding_rules.md` を基準に判定すること。
- 閉域運用、外部依存、個人情報保護、上書き禁止を重点確認すること。

### レビュー対象

- 対象ファイル:
- 想定利用環境:
- 懸念点:

### 出力形式

- 重大（修正必須）
- 中（修正推奨）
- 軽微（任意）
- 良い点
- 最小修正案

---

## 4. README作成依頼テンプレート

以下の前提でREADMEを作成してください。

- `docs/00_policy.md` と `docs/01_ai_coding_rules.md` を前提とすること。
- `docs/06_readme_template.md` の全項目を埋めること。
- 利用者が短時間で理解できる文体にすること。

### 対象情報

- ツール名:
- 目的:
- 主要機能:
- 入力/出力:
- 利用環境:

## 5. リリース前チェック依頼テンプレート

以下の前提で、リリース可否をチェックしてください。

- `docs/00_policy.md` と `docs/01_ai_coding_rules.md` を前提とすること。
- `docs/05_release_checklist.md` を使って判定すること。
- 判定結果は「OK / 要修正 / 保留」で示すこと。

### 対象

---

## 6. 共通部品化を検討する依頼テンプレート

以下の前提で、共通部品化の要否を評価してください。

- `docs/00_policy.md` と `docs/01_ai_coding_rules.md` を前提とすること。
- 先に共通化ありきで進めず、重複実装が複数回あるかを確認すること。
- 導入コストと保守負荷を併記すること。

### 評価対象

- 重複している処理:
- 登場箇所:
- 現在の問題:

### 出力してほしいもの

- 共通化すべき / まだ不要 の判定
- 判定理由
- 最小構成の共通化案（必要な場合のみ）

- コードやビルド設定は変更しないこと。
- 閉域運用・個人情報保護・説明責任を明確化すること。

### 更新対象

### 出力してほしいもの

- 変更後の文書
- 変更点の要約
- 他文書との整合確認結果
